## 2026-10-09：深色提示框修复

DSH 0.2.0-rc.2 的原生 Toast 使用 `--dsw-alias-toast-label`，Tooltip 使用固定白色文字。原主题在深色模式把两者的底色改为浅色，遗漏了提示文字的配对，造成浅底白字。本次显式设置 Toast 的文字颜色，并将深色 Toast 和 Tooltip 底色改为 `#253138`；没有改变提示的位置、动画和交互。

九项自动测试通过，包括新增的深浅模式对比度回归。使用官方桌面包内的 Toast / Tooltip 样式及发布加载器转换后的主题 CSS，在 Edge 中测得：浅色 Toast 12.61:1、Tooltip 14.84:1；深色 Toast 11.24:1、Tooltip 13.33:1。

本机已安装插件与 `.dsh/skins/rhine-lab` 同步更新，旧素材已备份。完全关闭后的官方 DSH 再次启动自动加载了修正版，实际点击已有归档会话验证提示为深底浅字。未归档、取消归档或发送消息。

同时检查官方 Codex 26.1002.7124.0 的原生提示组件与已加载的莱茵生命主题。在实际渲染器中临时放置不可见的同类 CSS 元素，读取计算颜色后立即移除；深色普通、成功、警告、错误及两种实色样式的对比度分别为 10.96、8.39、7.42、6.46、10.96、4.57:1。未发现相同的浅底白字问题，没有修改 Codex 的主题或当前会话。这项验证覆盖 CSS 渲染配色，未人为触发真实业务错误提示。

本次修复作为 DSH 1.1.2 打包，新增提示对比度回归测试；不更新 Codex 1.0.0 的 Release 附件。正式发布包保留安装器的备份和更新时保留用户设置的行为。

日期：2026-10-05。网页回归使用独立 DSH_HOME、空白工作区和 Edge 无头浏览器；桌面检查使用官方客户端中的空白会话。没有发送消息或调用模型 API。公开预览图仅来自隔离工作区。

## 已验证

发布版加载器接受 v2 清单，CSS 转换与 token 审核没有警告。素材引用、安装目标和备份由七项自动测试检查。重复安装保留原来的皮肤选择；显式激活保留背景控制和未知配置字段；无效的现有状态文件会阻止激活写入。

将发布 TGZ 通过普通 `dsh plugin` 命令安装到全新的隔离 profile，确认只安装主题插件即可带入皮肤中心，并在首次启动自动选中莱茵生命。该 profile 的背景、设置页、深浅切换、恢复默认、刷新保存和移动视口检查全部通过，主题资源没有失败请求。自动测试还确认后续启动和主题包更新保留用户已经修改的选择。

实际网页端可以加载莱茵生命、恢复官方默认、重新应用主题，刷新后仍保留主题和深浅选择。浅色与深色的聊天、侧栏、设置弹窗均显示对应素材。预览图来自这次空白工作区实测。
